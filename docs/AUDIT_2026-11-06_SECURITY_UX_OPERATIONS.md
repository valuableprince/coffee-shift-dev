## Безопасность
### Положительные наблюдения
1. **Небольшая поверхность сетевых атак:** в проверенных 100 `.gd` не найдены вызовы `HTTPRequest`, `HTTPClient`, `WebSocket`, `OS.execute`, `OS.create_process`, `OS.shell_open`, `str_to_var`, `bytes_to_var`. Динамические `load(path)` у аудио и торговых ассетов используют фиксированный перечень `res://`, а не путь из сохранения.
2. **Данные карьеры:** `scripts/systems/restoration_save_manager.gd` ограничивает размер файла 4 МиБ, проверяет JSON и версию формата, адрес ячейки, SHA-256 содержимого и схему игрового состояния; применяет временный файл, проверку записи, резервную копию `.bak` и восстановление транзакций. Это снижает риск потери прогресса от повреждения файла. SHA-256 здесь **не защищает от намеренного подделывания локального сохранения** — и не должен считаться механизмом авторизации.
3. **CI:** обе конфигурации ограничивают GitHub Actions token до `contents: read`; архив исполняемого Godot скачивается с проверкой фиксированного SHA-256. Не обнаружено передачи секретов или прямого исполнения произвольных данных сохранения.

### Недочёты
- **SEC-01 · P0 для коммерческого выпуска.** `docs/AUDIO01_LICENSES.md`: у `radio_09_ambient_space.ogg` и `radio_10_dreamy.ogg` есть только вторичное заявление CC0 без достаточного первичного доказательства. Нельзя считать такие записи очищенными для продажи. До выпуска найти первичные свидетельства прав либо заменить композиции; сверить правовую цепочку всего комплекта. См. [Issue #3](https://github.com/valuableprince/coffee-shift-dev/issues/3).
- **SEC-02 · P2.** `.github/workflows/godot-ci.yml` и `audio01-music.yml` используют `actions/checkout@v4` и `actions/upload-artifact@v4` как изменяемые version tags. Для устойчивой защиты от компрометации supply chain рекомендуется закрепить точные commit SHA, оставить минимальные permissions.
- **SEC-03 · P2.** Настройки `scripts/systems/game_settings.gd:40-54` пишутся напрямую в `user://coffee_shift_settings.cfg`, без временного файла и backup. Это риск потери настроек при аварийном завершении (не потеря карьеры). В торговой сцене `shift_world.gd:843` также игнорируется код ошибки записи.

## Удобство игрока
- **UX-01 · P1, подтверждено.** `scripts/trade/shift_hud.gd:64` показывает `M / P — музыка / мелодия`; `scripts/ui/garage_hud.gd:59` показывает `M — музыка`. В AUDIO-01 `scripts/audio/audio01_director.gd:280-282` старые кнопки не работают; реальный интерактив радиоприёмника — **E**, а громкость находится в настройках. Подсказки вводят игрока в заблуждение. Исправить обе и покрыть тестом соответствия.
- **UX-02 · P2.** `project.godot` задаёт фиксированные клавиши; в `scripts/ui/main_menu.gd` не предусмотрено переназначение управления. Нужны настройки клавиш или хотя бы единая таблица актуальных действий, проверка нескольких раскладок, контекстное обучение первой смене.
- **UX-03 · P2.** В настройках есть лишь три оконных разрешения (1280×720, 1600×900, 1920×1080), нет явного масштабирования интерфейса/шрифта. Провести оценку доступности: высокий DPI, слабое зрение, переносимость подсказок, цветовой контраст, выполнение полного заказа без внешнего руководства. Результатов пользовательского тестирования пока нет.
- **UX-04 · положительное.** Есть подтверждение перезаписи карьеры, отдельные ручные/автосохранения, текстовое сообщение при ошибке сохранения прогресса, настройки постепенного показа диалогов и компактная диалоговая панель.

Задача: [Issue #5 — UX](https://github.com/valuableprince/coffee-shift-dev/issues/5).

## Эксплуатация и тестирование
- **OPS-01 · P1.** `.github/workflows/audio01-music.yml` запускается на `push` только в `feat/audio01-music-integration`, **не на `main`**; AUDIO-01 не был повторно проверен своим специализированным workflow после merge. Добавить `main` и проверять для следующих изменений.
- **OPS-02 · P1.** Общий workflow запускает лишь `tests/dev03_domain.gd`, `tests/career_transactions.gd`, `tests/prototype_music_smoke.gd`. В репозитории есть 30 тестовых `.gd`, но большинство сценарных, UI, сохранений и 3D-тестов не входят в контроль `main`. Расширить matrix с лимитами и реальным GL Compatibility / Xvfb, не просто headless dummy.
- **OPS-03 · P1, подтверждено по коду.** `tests/new_assets_integration.gd:54` читает несуществующий в публичном дереве `res://docs/asset-integration/new-assets-sources.json`. `tests/visual_polish.gd:84` читает отсутствующий `res://docs/screenshots/visual-polish/before-metrics.json`. Эти тесты с высокой вероятностью упадут при запуске; минимальные проверочные данные нужно включить в публичную копию либо переписать тесты на автономные fixtures. Это **статическое заключение**, а не результат выполненного тестового прогона.
- **OPS-04 · P1.** Не включены воспроизводимый Windows export preset и автоматическая Windows-сборка; `export_presets.cfg` находится в `.gitignore`. Нет подтверждения запуска EXE, совместимости видеодрайверов, корректности путей к пользовательским файлам на Windows, обновления версии и установки через VK Play. Нужна нативная приёмка с артефактом и хешем.
- **OPS-05 · P1 перед релизом.** Аудиотреки ещё не приведены к MUSIC-25: ряд радиозаписей имеет моно/192 кГц и низкий битрейт; гаражный трек 16 кГц. Не измерены LUFS, true peak, качество швов и слуховой баланс. Формальное перекодирование не улучшит качество оригинала. См. Issue #3.
- **OPS-06 · P2.** `assets/audio/footsteps/footstep_concrete_004.ogg` отсутствует в публичном репозитории; теперь загрузчик безопасно пропускает этот необязательный ресурс, но набор шагов неполон. Восстановить исходные байты и сверить Git SHA при наличии разрешённого пути передачи.
- **OPS-07 · P2.** Исторические `docs/AUDIO01_REPORT.md` и `docs/PUBLIC_MIGRATION.md` сохраняют формулировки о Draft PR и ещё не завершённом merge. Обновить жизненный цикл документации, отделить зафиксированную историю от актуального состояния.
- **OPS-08 · P2.** Устаревший прототип `scripts/systems/game_state.gd` сохраняет JSON напрямую без лимита/backup; его вызывает только `scripts/legacy/cafe_prototype.gd`, а не основной сохранитель карьер. Изолировать как legacy или удалить из релизного набора после проверки миграции.

Задача: [Issue #4 — CI / Windows / fixtures](https://github.com/valuableprince/coffee-shift-dev/issues/4).

## Ограничения заключения
Результаты CI подтверждают только конкретные запущенные сценарии на Linux Godot 4.3. Нельзя называть игру полностью протестированной, коммерчески готовой, свободной от уязвимостей или гарантированно работоспособной в Windows без самостоятельной приёмки. Аудит **не меняет** игровой код, ресурсы и приватный репозиторий.
